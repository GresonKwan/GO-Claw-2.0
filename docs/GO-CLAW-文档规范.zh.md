# GO CLAW 文档规范

> 目的：高标准（任何改动可追溯、可验证）+ 高效率（小改动零文书）。
> 核心原则一句话：**当前事实进基线，历史行为进台账，设计进 spec，计划带状态，事实可复核。**

## 1. 文档分层（各有唯一职责，不重复记录）

| 层 | 文件位置 | 记什么 | 什么时候写 |
|----|----------|--------|-----------|
| 当前事实 | `docs/GO-CLAW-项目事实与发布基线.zh.md` | 当前代码/服务器/GitHub/发布状态与不可变条件 | 外部状态复核或事实变化时 |
| 台账 | `docs/GO-CLAW-变更台账.zh.md` | 已经发生的行为/配置/接口变更历史 | 随 commit 同批提交（见 §3） |
| 设计 | `docs/superpowers/specs/<日期>-<主题>-design.md` | 为什么这么做、方案权衡 | 有方案决策时；需标注确认状态 |
| 计划 | `docs/superpowers/plans/<日期>-<主题>.md` | 怎么做、步骤拆解 | 多步骤工作；完成后标状态 |
| 专题 | `docs/<主题>.zh.md` | 持续演进的系统说明（如计费体系） | 系统上线时建立，之后持续更新 |

**禁止**：同一事实在两处各写一份操作正文（允许当前基线写结论、专题写步骤并互相链接）。计划中的目标不得写成已部署现状。commit message 是台账条目的素材，不是替代品。

### 1.1 冲突优先级

1. 带验证日期的项目事实基线；
2. 当日只读复核得到的代码、GitHub、服务器证据；
3. 已上线专题运维文档；
4. 已确认设计；
5. 实施计划；
6. 历史聊天和快照。

发现冲突时先停止发布、更新事实基线和台账，再继续实现。不得从旧 plan 反推服务器现状。

## 2. 台账条目格式

每条目必须包含五要素，缺一不可：

```
| 改动内容（一句话） | 原因 | commit 哈希 | 验证方式 | 关联文档（无则省） |
```

- **改动内容**：写"变成什么样"，不写"改了一下"。含关键参数值（如"图 20s/15 张·时"）。
- **commit 哈希**：推送后补全短哈希；本地先写 `（待推送）`，推送后必须回填。
- **验证方式**：测试文件名 / 现场验证步骤 / "配置变更，无需测试"。
- 运营侧（服务器/后台）变更记入"运营侧变更"节，注明日期与操作内容。

## 3. 何时必须记账（强制） vs 何时不用（豁免）

**必须**（随 commit 同批）：
- 用户可见行为变更（含默认值、频次、文案、错误提示）
- 配置项/环境变量/接口路径的新增、修改、废弃
- 数据迁移与持久化格式变更
- 安全相关行为（鉴权、配额、密钥处理）

**豁免**（commit message 足够）：
- 纯格式化、重命名、注释、测试补充
- 不改变行为的内部重构
- lint/CI 修复

判断不准时记账——多记一条的成本远低于漏记。

## 4. 精确性规则（高标准的核心）

1. **可验证**：文档中的路径、URL、模型名、行号、commit 哈希必须与代码/部署实际一致；写之前亲自查证，不凭记忆。
2. **改配置同步改文档**：改代码里的默认值/路径时，同 commit 检查文档索引里登记过的专题文档是否需要同步。
3. **决策变更不删历史**：原计划被推翻时，在原文处加"（已变更，见台账 YYYY-MM-DD）"注记，保留原文。
4. **状态标记**：plan 完成后在标题下加"状态：已完成/已废弃（原因）"；spec 确认后加"已获确认"。
5. **外部事实带日期**：服务器地址、镜像 digest、渠道、域名、GitHub Secret/Variable 是否存在、CI run 和发布 URL 都写明复核日期与命令；Secret 只记名称和存在性，不记内容。
6. **目标/现状分栏**：尚未上线的 schema、endpoint、渠道、密钥轮换或 CI 产物必须标“目标”；只有现场验证通过后才能移入“已验证现状”。
7. **计划基线检查**：执行计划前先读项目事实基线；计划与其冲突时，计划自动暂停而不是自行选边。

## 5. commit message 规范

Conventional Commits 英文短句：`<type>(<scope>): <what>`，body 写**为什么**。
type：feat / fix / docs / test / build / ci / style / chore。一个 commit 只做一件事；不相关的改动分开提交。

## 6. 提交前自查清单（30 秒）

- [ ] 行为/配置变更？→ 台账条目已写，commit 哈希回填
- [ ] 文档里的路径/模型名/URL 与代码一致？
- [ ] 相关测试已更新并通过？
- [ ] 新文档已登记到台账的文档索引？
- [ ] 服务器/GitHub/CI 事实变化？→ 项目事实与发布基线已同步并带复核日期
- [ ] 文档是否把“计划目标”误写成“当前已经存在”？
