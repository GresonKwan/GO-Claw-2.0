# GO CLAW 客户可见层换牌与中文锁定设计

日期：2026-08-14
状态：已获用户逐节确认

## 1. 目标

在不改动 QwenPaw 核心运行协议的前提下，将 Windows 便携产品及 Web UI 的所有客户可见品牌统一为 `GO CLAW`，将产品语言固定为简体中文，删除顶部导航中的文档、GitHub 和语言入口，并使用现有智能体机制预置 5 名面向业务场景的数字员工。

改造后的便携版仍须保持现有能力：从任意 U 盘盘符和中文路径双击启动核心、自动打开 Web UI、保持单实例，并将运行数据绑定到便携目录。

## 2. 已确认决策

- 客户可见名称统一为全大写 `GO CLAW`。
- 采用“完整客户层换牌、内部兼容标识不变”的实施路径。
- 顶栏使用 V3 Hybrid 横版 Logo，显示高度为 24px。
- 前端语言固定为 `zh`，同时把后端语言偏好同步为 `zh`。
- 不提供任何系统语言或手动语言切换入口。
- 删除桌面端和移动端中的文档资料、GitHub 入口。
- 保留代码模式、主题切换、版本号与更新状态。
- 客户界面中的“智能体 / Agent”术语统一为“数字员工”。
- 使用现有智能体机制提供 5 名员工：通用数字员工、营销获客、内容生产、数据处理、商业分析。
- 4 名专业员工默认启用并置顶，但保持普通智能体原有的可编辑、停用和删除行为。
- 专业员工通过一次性的 `presets-v1` 启动迁移创建，用户删除后不自动重建。

## 6. 中文锁定

前端国际化改为单语言模式：

- 只导入并注册 `zh.json`；
- `lng` 与 `fallbackLng` 均固定为 `zh`；
- 不读取 `navigator.language`；
- 忽略并清除历史 `localStorage.language`；
- HTML `lang` 固定为 `zh-CN`；
- 删除桌面顶栏语言切换组件；
- 删除移动端菜单的语言子菜单；
- 启动时调用现有语言 API，将后端偏好设置为 `zh`。

后端同步失败时记录错误，但不得阻塞 UI 启动；前端仍必须显示中文。现有其他语言资源可以保留在源码中作为上游同步参考，但不得进入运行时语言注册表或出现在 UI 入口中。

客户界面统一使用“数字员工”，包括但不限于：

- 当前数字员工；

## 9. 预制数字员工

### 9.1 身份与顺序

| 顺序 | 客户名称 | 内部 ID | 角色 |
| --- | --- | --- | --- |
| 1 | 通用数字员工 | `default` | 日常问答、文件阅读、任务规划和跨岗位协调 |
| 2 | 营销获客 | `marketing-growth` | 市场调研、客户画像、竞品分析、获客策略、活动策划、线索整理和营销文案 |
| 3 | 内容生产 | `content-production` | 选题、文章、社媒文案、图片、视频脚本、分镜和媒体生成 |
| 4 | 数据处理 | `data-processing` | Excel/CSV 清洗、合并、公式、统计、图表和结构化输出 |
| 5 | 商业分析 | `business-analysis` | 行业、竞品、经营指标、市场机会、风险和决策报告 |

默认选中 `default`。4 名专业员工初始状态为启用并置顶，选择器按表格顺序显示，因此全新初始化后的标签为“当前数字员工（5）”。

### 9.2 能力配置

- 通用数字员工：文件阅读、任务规划和通用工具，不改变核心 `default` 身份。
- 营销获客：网页调研、文件读取、Word、PPT 和 Excel 技能；中文系统提示词要求输出客户画像、渠道策略、活动方案或线索表等可执行结果。
- 内容生产：Word、PPT、PDF、Qwen-Image 和 Wan 2.7；中文系统提示词覆盖选题、文案、图片提示词、视频脚本、分镜和成品生成。
- 数据处理：Excel、文件读取和 PDF；中文系统提示词要求保留原始数据、记录处理步骤并输出可追溯结果。
- 商业分析：网页调研、Excel、Word、PPT 和 PDF；中文系统提示词要求引用依据，并明确区分事实、假设和推断。

每名员工使用独立工作区、中文系统提示词和技能集合。模型与 API 配置沿用现有用户配置，预置文件中不得包含任何 API Key。

Qwen-Image 与 Wan 2.7 插件随产品打包并绑定到内容生产员工。缺少 DashScope API Key 时，内容生产员工仍可完成文字、提示词、脚本和分镜任务；调用图片或视频生成前必须明确提示用户配置凭据，不能伪造生成结果。

### 9.3 生命周期

- `default` 按现有核心规则不可删除。
- 4 名专业员工是普通智能体配置，用户可修改名称、提示词、模型、技能和工具，可取消置顶、停用或删除。
- 本轮不新增“恢复预置配置”功能。
- 用户自行创建的数字员工保持现有全部行为。

## 10. `presets-v1` 初始化迁移

初始化在现有 `ensure_default_agent_exists()` 完成后执行，不修改智能体执行引擎：

1. 检查 `$QWENPAW_WORKING_DIR/.migrations/go-claw-presets-v1.json` 完成标记；标记至少包含预置版本和完成时间。
2. 无标记时保留现有配置，并只创建缺失的 4 个稳定 ID。
3. 已存在同 ID 员工时保留其工作区、模型、提示词、技能和工具，不覆盖用户数据。
4. `default` 仍使用上游原始名称时改为“通用数字员工”；已经被用户改名时保留用户名称。
5. 为新建的专业员工写入独立工作区、中文提示词、技能、工具、启用状态、置顶状态和固定顺序。
6. 所有目标均成功存在后才通过临时文件加原子替换写入 `presets-v1` 完成标记。
7. 中途失败时不写完成标记；下次启动只重试缺失项。

完成标记一旦存在，后续启动不再补建员工。因此用户删除专业员工后不会被系统恢复。迁移对全新 U 盘数据目录和已运行旧版本的数据目录各执行一次，并不得改变便携数据目录绑定规则。

## 12. 错误处理

- 品牌资源缺失时构建必须失败，不允许静默回退到旧 Logo。
- 后端语言同步失败只记录错误，不能阻止中文 UI 启动。
- 预置迁移部分失败时不写完成标记，下次启动安全重试，已创建员工不得重复或覆盖。
- 内容生产缺少 DashScope API Key 时显示可执行的配置提示，文字能力保持可用。
- 生成 Windows 图标失败时构建必须失败，避免发布旧图标或空图标。
- 客户可见字符串扫描发现旧品牌时测试失败；允许列表仅包含第 5 节列出的内部兼容场景。
- 便携启动、盘符迁移、单实例或 UI 健康检查失败时不得上传正式测试产物。
