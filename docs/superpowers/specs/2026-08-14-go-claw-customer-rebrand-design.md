# GO CLAW 客户可见层换牌与中文锁定设计

日期：2026-08-14  
状态：已获用户逐节确认

## 1. 目标

在不改动 QwenPaw 核心运行协议的前提下，将 Windows 便携产品及 Web UI 的所有客户可见品牌统一为 `GO CLAW`，将产品语言固定为简体中文，并删除顶部导航中的文档、GitHub 和语言入口。

改造后的便携版仍须保持现有能力：从任意 U 盘盘符和中文路径双击启动核心、自动打开 Web UI、保持单实例，并将运行数据绑定到便携目录。

## 2. 已确认决策

- 客户可见名称统一为全大写 `GO CLAW`。
- 采用“完整客户层换牌、内部兼容标识不变”的实施路径。
- 顶栏使用 V3 Hybrid 横版 Logo，显示高度为 24px。
- 前端语言固定为 `zh`，同时把后端语言偏好同步为 `zh`。
- 不提供任何系统语言或手动语言切换入口。
- 删除桌面端和移动端中的文档资料、GitHub 入口。
- 保留代码模式、主题切换、版本号与更新状态。

## 4. 客户可见品牌范围

以下位置统一显示 `GO CLAW`：

- Web UI 顶部横版 Logo；
- 登录页与后端启动等待页；
- 默认助手名称与头像；
- 浏览器标题、HTML 语言标记和 favicon；
- Tauri 窗口标题、产品显示名；
- Windows EXE 文件名、便携 ZIP 文件名及校验文件名；
- 安装包、卸载器、任务栏、窗口和快捷方式的名称与图标；
- 中文界面中面向客户的登录、更新、重启、兼容性和产品说明文案；
- 便携版中文 README 中的产品名称与启动文件名。

顶栏 Logo 采用 24px 高度，版本号紧邻 Logo 显示，并维持现有隐藏式 DevTools 点击手势。

## 5. 明确不改的内部兼容范围

以下内容保留现有 `QwenPaw/qwenpaw` 标识：

- Python 包名、模块路径和 CLI 命令；
- 后端进程与 sidecar 文件名；
- API 路径、HTTP header 与进程间协议；
- `QWENPAW_*` 环境变量；
- `.qwenpaw` 数据目录及内部工作区路径；
- `window.QwenPaw` 插件接口、插件类型和注册表；
- Tauri identifier；
- 日志标签、CSS 前缀和仅开发者可见注释；
- 技术命令、真实路径或兼容性字段中的 `qwenpaw` 字面值。

这条边界用于防止换牌影响现有后端、数据迁移、插件或单实例行为。客户文案可以解释产品为 `GO CLAW`，但必须保留技术命令和路径的真实拼写。

## 6. 中文锁定

前端国际化改为单语言模式：

- 只导入并注册 `zh.json`；
- `lng` 与 `fallbackLng` 均固定为 `zh`；
- 不读取 `navigator.language`；
- 忽略并清除历史 `localStorage.language`；
- HTML `lang` 固定为 `zh-CN`；
- 删除桌面顶栏语言切换组件；
- 删除移动端菜单的语言子菜单；
- 启动时调用现有语言 API，将后端偏好设置为 `zh`。

后端同步失败时记录错误，但不得阻塞 UI 启动；前端仍必须显示中文。现有其他语言资源可以保留在源码中作为上游同步参考，但不得进入运行时语言注册表或出现在 UI 入口中。

## 7. 顶部导航精简

桌面端删除：

- “文档资料”下拉菜单；
- 独立 GitHub 按钮；
- 语言按钮。

移动端删除：

- 语言子菜单；
- 教程、功能演示、更新日志、FAQ 和 GitHub 资源项；
- 仅用于打开这些资源项的信息菜单按钮。

保留：

- 插件注入的 `header.left` 与 `header.right` 插槽；
- 代码模式按钮；
- 主题切换按钮；
- 版本号、更新徽标、下载和安装状态。

删除导航入口不等于删除底层外链工具或产品功能。其他真正需要打开外部链接的功能仍可以使用现有安全外链能力。

## 8. Windows 产物命名

客户可见产物统一为：

- 便携启动器：`GO-CLAW-Portable.exe`；
- 便携压缩包：`GO-CLAW-Portable-2.0.1-Windows-x64.zip`；
- 校验文件：`GO-CLAW-Portable-2.0.1-Windows-x64.zip.sha256`；
- 安装版产品显示名、窗口标题和快捷方式：`GO CLAW`。

内部 `qwenpaw-backend.exe`、Python/Node runtime、数据目录和关闭协议保持不变。所有打包、校验、PowerShell 自动化和 GitHub Actions 断言必须跟随新的客户可见文件名更新。

## 9. 错误处理

- 品牌资源缺失时构建必须失败，不允许静默回退到旧 Logo。
- 后端语言同步失败只记录错误，不能阻止中文 UI 启动。
- 生成 Windows 图标失败时构建必须失败，避免发布旧图标或空图标。
- 客户可见字符串扫描发现旧品牌时测试失败；允许列表仅包含第 5 节列出的内部兼容场景。
- 便携启动、盘符迁移、单实例或 UI 健康检查失败时不得上传正式测试产物。

## 10. 测试与验收

实现遵循测试先行，先观察断言因旧行为而失败，再做最小修改。

- 预置 `localStorage.language=en` 并模拟英文系统语言，运行时仍解析为 `zh`；
- 启动时请求后端保存 `zh`；保存失败不阻塞渲染；
- 顶栏不存在语言、文档资料或 GitHub 控件；
- 移动端不存在语言或资源信息菜单；
- 顶栏 Logo 根据主题加载正确的 GO CLAW SVG，尺寸为 24px；
- 登录页、启动页和默认助手显示 GO CLAW 名称和资源。

### 10.2 静态品牌检查

扫描客户可见代码、HTML、Tauri 配置、便携说明和打包脚本，禁止残留面向客户的 `QwenPaw`。扫描必须使用明确允许列表，避免误改内部 API、命令、路径和插件接口。

### 10.3 构建与单元测试

- 前端单元测试；
- TypeScript 类型检查；

- Rust 单元测试；

### 10.4 Windows CI 验收

- 构建新的安装版和完整便携 ZIP；
- 校验 ZIP 与 SHA-256；
- 在两个模拟盘符间迁移，并在中文路径启动；
- 第一次双击启动核心并自动打开 Web UI；
- 第二次双击保持相同 PID/端口并聚焦或打开客户端；
- API 版本、Web 首页和聊天输入框可用；
- UI 显示 GO CLAW 品牌；
- UI 不显示 QwenPaw、文档资料、GitHub 或语言切换按钮；
- 数据目录仍位于便携目录，外部项目路径不被迁移或破坏；
