# GO CLAW 运行时品牌提示词与批次凭证设计

日期：2026-08-15
状态：已获用户逐节确认

## 1. 目标

本设计在现有 GO CLAW Windows 便携版已经能够从 U 盘双击启动、自动打开 Web UI 的基础上，完成两项小范围增强：

1. 精确修正进入数字员工系统提示词的旧品牌来源，使客户可见的身份、自我介绍和普通运行说明统一使用 `GO CLAW`，不再由系统提示词诱导模型自称 `QwenPaw Agent`。
2. 支持小批量 U 盘交付时通过一个明文 JSON 首次导入共享的 LLM 与 DashScope API Key，预选默认 LLM，并让 Qwen-Image 与 Wan 2.7 工具对所有现有及未来数字员工默认可用。

本设计补充并覆盖 `2026-08-14-go-claw-customer-rebrand-design.md` 中“模型与 API 配置保持完全由用户手工完成”“媒体工具仅绑定内容生产员工”以及“产物不得包含预配置 API Key”的相关约束。其他已经确认的客户层换牌、中文锁定、五名数字员工和便携路径边界保持不变。

## 2. 已确认决策

- 仅修正提示词来源，不增加聊天输出替换或过滤层。
- 客户可见的运行身份统一为 `GO CLAW`。
- 删除系统提示词中的旧 GitHub 和旧文档入口。
- 内部 Python 包、进程、CLI、环境变量、路径和兼容字段继续使用现有 `qwenpaw/QWENPAW_*` 名称。
- API Key 采用小批量共享方式，并由交付方设置调用额度。
- 允许交付配置 JSON 以明文保存 Key。
- 凭证只在首次启动时导入；成功后不再覆盖用户在客户端做出的修改。
- LLM Key 与媒体 Key 可以不同。
- Qwen-Image 与 Wan 2.7 共享一份全局 DashScope Key。
- 五个媒体工具对所有现有及未来数字员工默认可用，由现有 Agent Loop 的自动工具选择判断是否调用。
- 不实现对话中途修改工具启用状态的动态工具加载器。

## 3. 现状与直接原因

### 3.1 旧品牌来自运行时系统提示词

通用员工的中文 `BOOTSTRAP.md` 没有写入 `QwenPaw Agent`。截图中的旧品牌自我介绍来自每次请求都会注入的环境上下文；当前环境上下文明确告诉模型：

- 它运行在 QwenPaw 中；
- QwenPaw 的旧 GitHub 地址；
- QwenPaw 的旧文档地址。

因此只改前端 Logo、员工名称或工作区模板不能解决该问题。必须修改最终系统提示词的运行时来源，并对实际组装结果进行测试。

### 3.2 LLM 与媒体凭证当前分散

LLM 服务商 Key 当前由 `ProviderManager` 保存到便携目录的 `secrets/providers/`，敏感字段经过现有 secret store 加密；默认模型另存为 `active_model.json`。

媒体插件不同：Qwen-Image 与 Wan 2.7 目前从当前数字员工的 `agent.json` 工具配置读取 `api_key`。这会把同一 DashScope Key 重复保存到多个工具和员工，并导致新建员工必须手动启用、逐项配置。

本设计将 DashScope Key 导入全局 DashScope 服务商配置，并让媒体工具在没有员工级覆盖值时读取该全局 Key。

## 4. 客户可见品牌提示词设计

### 4.1 运行身份

环境上下文中的产品身份改为简短、固定的中文表述：数字员工属于 `GO CLAW`，由当前选中的模型提供推理能力。系统提示词不再包含旧项目名称、旧 GitHub 地址或旧文档地址。

身份描述不得声称模型由 GO CLAW 自研，也不得混淆产品、模型服务商和实际模型名称。

### 4.2 精确修正范围

检查并修正以下会进入客户对话上下文的来源：

- 每次请求注入的环境上下文；
- 首次启动引导与通用员工身份提示；
- 五名默认数字员工实际使用的 `AGENTS.md`、`SOUL.md`、`PROFILE.md`；
- 五名员工可读取的技能说明和客户可见工具说明；
- 内置模板或运行命令中客户可见的默认员工名称回退；
- 插件注册到系统提示词的客户可见提示片段。

内置 QA 等不属于五名默认员工、但可以通过客户 UI 创建或启用的模板，也应移除其客户可见旧品牌身份。技术诊断模板中必须保留的真实命令、环境变量和路径属于内部兼容范围，不进行虚假改名。

### 4.3 用户工作区保护

不批量覆盖用户已经修改的 `AGENTS.md`、`SOUL.md` 或 `PROFILE.md`。运行时代码修正对现有 U 盘立即生效，因为环境上下文会在每次请求时重新组装。

如果工作区文件由旧版本原样生成且包含客户品牌文案，只有在能够通过精确内容或已知模板摘要证明文件仍是未修改模板时，才允许做一次性模板迁移。无法证明时保留用户文件。

### 4.4 不增加输出过滤

本轮不在流式响应、普通消息、代码块、工具结果或前端渲染层增加 `QwenPaw -> GO CLAW` 替换。验收目标是系统提供给模型的身份与客户提示来源正确，而不是修改模型已经生成的任意文本。

这可以消除已定位的确定性诱因，但不对第三方模型自行生成任意词语作数学意义上的保证。

## 5. 批次凭证文件

### 5.1 路径

便携根目录支持以下文件：

```text
GO-CLAW-Portable.exe
GO-CLAW-Config/
├── credentials.example.json
└── credentials.json
```

路径始终相对于当前 EXE 解析，因此 U 盘盘符从 E、F、G 或其他盘符变化时无需修改配置。

仓库和正式公共 CI 产物只包含没有真实 Key 的 `credentials.example.json`。真实 `credentials.json` 必须被 Git 忽略，由交付方在写入 U 盘前复制。无需重新构建 EXE。

### 5.2 严格 JSON 结构

第一版结构如下：

```json
{
  "schemaVersion": 1,
  "batchId": "2026-08-A",
  "llm": {
    "providerId": "kimi-cn",
    "modelId": "kimi-k2.5",
    "apiKey": "填写批次 LLM API Key"
  },
  "dashscope": {
    "apiKey": "填写批次 DashScope API Key"
  }
}
```

规则：

- `schemaVersion` 固定为整数 `1`；
- `batchId`、两个服务商 ID/模型 ID 和 Key 均去除首尾空白后校验；
- JSON 拒绝未知字段，避免拼写错误被静默忽略；
- `llm.providerId` 必须是运行时已注册的服务商；
- `llm.modelId` 必须属于该服务商的已知模型；
- 如果 LLM 本身选择 `dashscope`，`llm.apiKey` 与 `dashscope.apiKey` 必须一致，避免同一全局服务商出现冲突凭证；
- Qwen-Image 默认使用插件 manifest 中的生成/编辑模型；Wan 2.7 继续使用插件内已经固定的文生视频、图生视频和参考生视频模型；
- 员工级工具配置仍可覆盖媒体模型、API 地址、超时和 Key。

## 6. 首次导入流程

导入只在 Windows 便携模式执行。顺序如下：

1. 便携启动器解析 EXE 相邻的 `data/` 与 `secrets/` 路径。
2. 后端完成 ProviderManager、内置插件和数字员工初始化。
3. 检查 `data/.go-claw-credentials-imported.json`。
4. 完成标记存在时直接跳过，不读取或覆盖 `credentials.json`。
5. 标记不存在且凭证文件不存在时保持现有行为，允许用户通过客户端配置。
6. 标记不存在且凭证文件存在时，先读取并完整校验 JSON；校验期间不写任何用户配置。
7. 将 `llm.apiKey` 保存到指定服务商，并激活 `providerId/modelId` 为全局默认模型。
8. 将 `dashscope.apiKey` 保存到全局 DashScope 服务商，但除非 LLM 本身选择 DashScope，否则不把 DashScope 模型设为聊天默认模型。
9. 为所有已经存在的数字员工设置五个媒体工具为默认启用；该步骤不把 Key 复制到员工配置。
10. 从磁盘重新读取服务商、活动模型和员工工具状态，确认导入结果。
11. 全部成功后，通过同目录唯一临时文件加原子替换写入完成标记。

完成标记只包含：

```json
{
  "schemaVersion": 1,
  "batchId": "2026-08-A",
  "sourceSha256": "凭证文件内容摘要",
  "importedAt": "UTC ISO-8601 时间"
}
```

完成标记、日志、异常、测试输出和 API 响应不得包含任何 Key。

只要完成标记存在，后续对 `credentials.json` 的修改就不会自动生效，用户在客户端所做的模型或工具修改也不会被覆盖。交付方需要显式重新导入时，可删除完成标记后重启；这一次启动重新以 JSON 为准。

## 7. 全局媒体凭证解析

五个媒体工具采用统一解析顺序：

1. 当前数字员工对应工具配置中的非空 `api_key`；
2. 全局 DashScope 服务商配置中的非空 Key；
3. 均不存在时返回现有中文缺 Key 提示，并且不得发起网络请求。

工具级 `endpoint`、`timeout` 和 Qwen-Image `model` 继续按当前工具配置及插件默认值解析。全局 DashScope 聊天服务商的兼容模式 URL 不作为媒体 API endpoint 使用，避免混淆两类接口地址。

读取全局 Key 的逻辑应由一个共享帮助函数实现，Qwen-Image 和 Wan 2.7 不得各自复制 ProviderManager 访问与错误处理代码。

## 8. 媒体工具对所有数字员工默认可用

目标工具为：

- `generate_image_qwen`；
- `edit_image_qwen`；
- `text_to_video_wan`；
- `image_to_video_wan`；
- `reference_to_video_wan`。

插件 manifest 为这些工具声明“默认启用”。插件工具默认配置合并和插件同步逻辑必须读取该声明，不再对所有插件一律硬编码为禁用。

行为规则：

- 首次凭证导入时，将五个目标工具加入并启用到所有现有数字员工；
- 用户以后新建数字员工时，`ToolsConfig` 从插件 manifest 得到五个默认启用项；
- Agent Loop 继续使用已有 `tool_choice=auto`，根据用户意图决定是否实际调用；
- “默认可用”只表示模型能看到工具定义，不代表每轮都会调用或产生费用；
- 用户显式禁用某名员工的某个工具后，普通启动、配置加载和新版本默认合并都必须保留该禁用值；
- 本轮不新增工具搜索元工具，不在对话中途写回 `agent.json`，也不要求委托内容生产员工。

为了避免改变第三方插件的安全默认值，manifest 未声明默认启用时仍按禁用处理。只有本次两个内置媒体插件显式声明默认启用。

## 9. 错误与重试

- JSON 语法、字段、服务商或模型无效：不做导入、不写完成标记，记录不含 Key 的错误，Web UI 仍可启动并使用现有手工配置流程。
- Provider 或活动模型保存失败：不写完成标记，下次启动重试。
- 部分员工工具更新失败：不写完成标记；已成功写入的配置必须保持有效，下一次导入幂等补全。
- 全局 DashScope Key 不存在：媒体工具返回中文缺 Key 提示，不调用外部 API。
- 完成标记存在但用户后来删除某项配置：尊重用户修改，不从 JSON 自动恢复。
- `credentials.json` 是符号链接、目录或位于便携根目录之外：拒绝导入。
- 日志可以包含文件路径、批次号、服务商 ID 和模型 ID，但不得包含请求体、完整 JSON 或 Key。

## 10. 安全边界

用户已经接受共享 Key 以明文保存在交付 JSON 中，并通过服务商额度控制降低风险。产品仍需明确：

- 拿到 U 盘的人可以复制该明文 Key；
- 现有 `secrets/` 加密用于避免普通配置文件直接暴露凭证，不能替代 BitLocker 或物理保管；
- 真实凭证不得提交到 Git、GitHub Actions secret 以外的日志、公共 Artifact 或测试快照；
- HTTP/API 返回不得回显完整凭证；
- 前端查询服务商和工具配置时继续只返回掩码值。

## 11. 测试与验收

### 11.1 提示词合同

- 组装五名默认数字员工的真实最终系统提示词，客户身份为 `GO CLAW`；
- 通用员工存在 `BOOTSTRAP.md` 时仍使用 GO CLAW 身份；
- 新建普通数字员工的系统提示词也使用 GO CLAW 身份；
- 最终提示词中不存在客户品牌用法的 `QwenPaw`、旧 GitHub 地址或旧文档地址；
- 允许真实内部命令、环境变量和路径中的兼容字面值；
- 不存在聊天输出替换逻辑。

### 11.2 凭证导入

- 无 JSON 时零改动并正常启动；
- 有效 JSON 首次导入 LLM Key、全局活动模型和全局 DashScope Key；
- 完成标记在所有验证通过后才写入，且不含 Key；
- 标记存在时即使 JSON 已变化也不重新导入；
- 删除标记后可以显式重新导入；
- 空白 Key、未知字段、未知服务商、未知模型、错误 schema、符号链接和路径逃逸均被拒绝；
- 任一步骤失败均不写标记，下次启动可幂等重试；
- 日志、异常和 API 响应不泄露 Key。

### 11.3 媒体工具

- 五名现有员工在首次导入后都默认拥有五个媒体工具；
- 导入完成后新建的普通员工也默认拥有并启用五个媒体工具；
- 员工级 Key 优先于全局 DashScope Key；
- 员工级 Key 为空时使用全局 Key；
- 两处均为空时不触发任何 DashScope 请求；
- 用户显式禁用后重启仍保持禁用；
- Qwen-Image 和 Wan 2.7 均通过同一个共享凭证解析入口；
- Agent Loop 能在工具自动选择模式中调用目标工具，不需要先修改员工配置。

### 11.4 便携与交付

- JSON 相对 EXE 解析，在 E、F、G 和中文目录中行为一致；
- 公共 ZIP 只含示例文件，不含真实 Key；
- 将真实 JSON 复制到解压目录后无需重新构建即可导入；
- Windows 局部 Runner 验证无手工模型配置即可聊天，并验证任一新建员工可以使用媒体工具；
- 原有盘符迁移、单实例、Web UI 自动打开和优雅退出验收继续通过。

## 12. 非目标

- 不重命名 `qwenpaw` Python 包、CLI、进程、环境变量、路径或插件 SDK；
- 不修改第三方模型输出的任意文本；
- 不新增聊天输出过滤或前端字符串替换；
- 不让 JSON 在每次启动时覆盖用户配置；
- 不实现在线授权服务器、短期令牌或按客户独立 Key；
- 不实现 Agent Loop 中途持久化启用/禁用工具；
- 不默认启用其他第三方插件工具；
- 不把真实 API Key 提交到源码仓库或公共 CI Artifact。
